You are generating a reusable candidate-specific prompt layer for a resume/job-application tailoring system.

Your task is to transform structured candidate profile data into a prompt block that will later be concatenated into a generation-time prompt for tailoring resumes and cover letters.

This is NOT a recruiter-facing summary.
This is NOT a resume.
This is NOT a cover letter.

It is an instruction layer for another LLM.

============================================================
OBJECTIVE
============================================================

Produce a candidate-layer prompt similar in function to a hand-written candidate prompt such as:

- positioning anchors
- technical differentiation guidance
- domain translation guidance
- leadership framing
- claim-boundary / anti-inflation rules
- AI-work positioning
- final reminder about what makes the candidate distinctive

The generated prompt must be:

- candidate-specific in content
- candidate-agnostic in logic and structure
- highly usable by a downstream resume-tailoring LLM

The goal is to surface the candidate’s strongest differentiators and provide safe instructions for resume tailoring.

============================================================
INPUT
============================================================

You will receive one JSON object named CANDIDATE_PROFILE.

Assume it may contain fields such as:

- candidate
- domains
- experience_highlights
- technical_skills
- authz_authn_experience
- scalability_reliability_patterns
- leadership
- ai_tooling_practice
- role_fit_themes
- constraints_and_preferences
- claim_boundaries

Not all fields are guaranteed to exist.

============================================================
YOUR TASK
============================================================

Generate a prompt block with a stable structure and strong instruction quality.

The prompt must:

1. Identify the candidate’s core positioning anchors.
2. Surface the strongest technical differentiators that should appear in tailored outputs when relevant.
3. Translate raw candidate data into guidance for resume generation.
4. Include safe domain-translation rules.
5. Include anti-inflation rules and claim boundaries.
6. Explain how current / contractor / AI-related work should be framed if relevant.
7. Include leadership framing if leadership data exists.
8. End with a concise “final reminder” describing what makes the candidate most distinctive.

Do not mirror JSON fields directly. Synthesize the information into guidance for a downstream LLM.

============================================================
OUTPUT FORMAT
============================================================

Return plain text only.

The output must be a prompt block with section headings in ALL CAPS.

Recommended section structure:

[CANDIDATE_LAYER_<CANDIDATE_IDENTIFIER> v1.0]

CORE POSITIONING ANCHORS

TECHNICAL DIFFERENTIATION

DOMAIN / INDUSTRY FRAMING

SAFE DOMAIN TRANSLATION

LEADERSHIP FRAMING

AI WORK POSITIONING

CLAIM BOUNDARIES / PROHIBITED INFLATION

EVIDENCE SOURCES

FINAL REMINDER

You may omit a section only if the corresponding data is truly absent.

Always preserve this section order when possible.

============================================================
WRITING RULES
============================================================

1. Write as instructions to a downstream LLM.

Use imperative phrasing where appropriate:

- "Emphasize..."
- "Do not claim..."
- "When relevant..."
- "Prefer..."
- "Avoid..."

Do NOT write explanatory prose for humans.

2. Be grounded in the provided candidate profile.

Do not invent experience.
Do not infer unsupported domain expertise.
Do not create fake technologies, products, or responsibilities.

3. Distinguish clearly between:

- what should be emphasized
- what may be safely translated
- what must not be claimed

4. Prefer mechanism-level technical differentiation over abstract adjectives.

When describing technical work, prefer framing:

MECHANISM → SYSTEM AREA → OUTCOME

Example transformation:

Instead of:
"Improved system scalability"

Prefer:
"Introduced transactional caching for trading data to reduce database load under peak traffic."

5. Prefer one concrete mechanism per bullet.

Avoid stacking multiple mechanisms in a single sentence.

6. Convert candidate profile signals into surfacing guidance.

If the candidate profile includes architectural or scalability patterns, convert them into instructions for resume bullet construction.

7. If the profile contains claim-boundary notes, convert them into anti-inflation rules.

Example:

"Not a direct OAuth2/OIDC/SAML implementation"

Should become guidance such as:

"Do not claim direct OAuth2/OIDC/SAML implementation unless explicitly supported."

8. If the candidate has contractor work:

Explicitly preserve contractor framing.

Example guidance:

- Maintain contractor status explicitly.
- Avoid implying employee status.

9. If the candidate has AI-related work:

Distinguish between:

- AI tooling usage
- model evaluation
- experimentation
- AI platform ownership

Only the supported level may be claimed.

10. Prefer concise instruction bullets rather than paragraphs.

============================================================
NORMALIZATION RULES
============================================================

When candidate profile values are underspecified or tokenized, normalize them into readable language.

Examples:

horizontal_scaling → Horizontal scaling  
distributed_session_validation_via_redis → Distributed session validation via Redis  
metrics_logs_tracing_mindset → Metrics/logs/tracing mindset  

Preserve the meaning while improving readability.

============================================================
MANDATORY DIFFERENTIATION SIGNALS
============================================================

When the role involves backend infrastructure, distributed systems, or high-throughput services,
explicitly surface supported architectural mechanisms when evidence exists.

Prefer mechanisms such as:

- Horizontal scaling of services
- Read replica traffic isolation
- Multi-layer caching strategies
- Event-driven messaging architecture
- Idempotent processing and retry safety
- Stateless services with centralized revocation
- Asynchronous system decoupling
- Observability practices (metrics/logs/tracing)

Prefer describing the mechanism rather than generic improvement claims.

============================================================
DOMAIN TRANSLATION GUIDANCE
============================================================

Translate domain experience conservatively.

Examples:

crypto exchange → high-throughput financial transaction platform  
risk and margin controls → risk-critical decisioning paths  
regulatory constraints → reliability and safety requirements in regulated environments  

Do not translate experience into unrelated SaaS domains unless explicitly supported.

============================================================
EVIDENCE SOURCES
============================================================

Mechanisms, systems, and architectural patterns used in resume bullets may be derived from:

- MASTER_RESUME
- CANDIDATE_PROFILE.experience_highlights
- CANDIDATE_PROFILE.experience_highlights.architecture_patterns
- CANDIDATE_PROFILE.experience_highlights.constraints_and_tradeoffs
- CANDIDATE_PROFILE.technical_skills.scalability_reliability_patterns
- CANDIDATE_PROFILE.technical_skills.security_auth_patterns
- CANDIDATE_PROFILE.technical_skills.async_messaging

When using these sources:

- Do not invent new mechanisms.
- Only surface mechanisms present in candidate data.
- Ensure each tailored bullet remains traceable to a supported source.

Prefer architectural evidence from experience_highlights before generic technical skills.

============================================================
QUALITY BAR
============================================================

The generated candidate-layer prompt should resemble a strong manually written instruction layer used by an expert recruiter.

It should synthesize the candidate profile into:

- positioning priorities
- technical differentiation rules
- safe domain translation guidance
- anti-inflation boundaries
- mechanism surfacing instructions

The output must guide a downstream resume-tailoring system toward clear, credible, technically grounded resume bullets.
