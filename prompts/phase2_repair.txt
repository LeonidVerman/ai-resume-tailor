Your job is to minimally modify a previously generated resume and cover letter JSON so that it passes validation, while preserving truthfulness and avoiding hallucinations.

INPUTS YOU WILL RECEIVE

ORIGINAL_OUTPUT_JSON (JSON with keys "resume" and "cover_letter")

VALIDATION_ERRORS (list of validation error strings)

WRITER_PACKET (Phase 1 output; contains required tokens and role constraints)

MASTER_RESUME (source of truth)

CANDIDATE_PROFILE (verified background)

JOB_DESCRIPTION (terminology reference only)

TASK (company and role)

OUTPUT FORMAT
Return JSON only:

{
"resume": "...",
"cover_letter": "..."
}

NON NEGOTIABLE TRUTH RULES

Do not invent facts.

Do not add employers, titles, dates, technologies, metrics, or scope not supported by MASTER_RESUME or CANDIDATE_PROFILE.

Do not modify employer names, titles, or dates.

Do not fabricate causal claims.

Changes must be minimal and directly tied to resolving VALIDATION_ERRORS.

GENERAL PRINCIPLE

WRITER_PACKET is the structured source of required tokens and role-level constraints.
When fixing validation issues, prefer guidance from WRITER_PACKET over reinterpreting JOB_DESCRIPTION.

REPAIR PROCEDURE

Step 1. Categorize VALIDATION_ERRORS into:

Missing required skills

Missing required metrics

Bullet count minimum failures

Mechanism minimum failures

Unsafe JD nouns

Structural formatting issues

Step 2. Fix Missing Required Skills

If VALIDATION_ERRORS contains:
Missing required skills: skill1, skill2, ...

2.1 Determine support
A skill is supported if:

The exact string appears in MASTER_RESUME, or

The exact string appears in CANDIDATE_PROFILE, or

The exact string appears in WRITER_PACKET as a required or allowed skill.

If not supported by these sources, do not add it.

2.2 Inject exact tokens
For each supported required skill not present in resume:

Insert the exact string verbatim into Technical Skills.

Prefer appending to an existing category.

If no suitable category exists, append under:
Other: skill1, skill2

If an Other line already exists, append to it.

Do not paraphrase.

Preserve exact casing and spacing.

Step 3. Fix Missing Required Metrics

If VALIDATION_ERRORS contains:
Missing required metrics: metric1, metric2, ...

3.1 Determine support
Metric must appear verbatim in MASTER_RESUME, CANDIDATE_PROFILE, or WRITER_PACKET.
If not supported, do not add.

3.2 Inject metric verbatim
For each supported required metric missing from resume:

Insert the exact string verbatim into the most relevant experience entry.

Preferred placement:

Parenthetical at end of role header line, or

Parenthetical at end of strongest bullet in that role.

Do not rephrase or alter formatting.

Step 4. Fix Mechanism Minimum Failures

If a role fails mechanism minimum:

4.1 Determine required count
Use WRITER_PACKET role-level constraints to understand expected mechanism density.

4.2 Only use supported mechanisms
A mechanism may be added only if it appears in:

MASTER_RESUME, or

CANDIDATE_PROFILE, or

WRITER_PACKET allowed mechanisms list.

4.3 Modify existing bullets only

Do not invent new initiatives.

Add short mechanism phrases using connectors such as:
via
using
through
by implementing

Do not change the underlying claim.

Keep bullets concise.

Step 5. Fix Bullet Count Minimum Failures

If a role fails bullet count minimum:

5.1 Prefer splitting compound bullets into two coherent bullets if supported by sources.

5.2 If still below minimum:

Add at most 1 to 2 bullets using only content explicitly present in MASTER_RESUME, CANDIDATE_PROFILE, or WRITER_PACKET.

5.3 If minimum cannot be satisfied without invention:

Preserve truth over passing validation.

Do not fabricate content.

Step 6. Fix Unsafe JD Terms

If VALIDATION_ERRORS includes unsafe JD nouns:

Remove unsupported JD-only terms.

Replace with adjacent supported phrasing if possible.

Do not imply unsupported experience.

Step 7. Final Pass

Before returning:

Confirm employer names, titles, and dates unchanged.

Confirm required supported skills appear verbatim in Technical Skills.

Confirm required supported metrics appear verbatim somewhere in resume.

Confirm role ordering unchanged.

Keep cover letter edits minimal unless required for validation.

Return JSON only.
