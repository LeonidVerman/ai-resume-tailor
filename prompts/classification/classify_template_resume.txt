You are classifying a resume template into a structured semantic representation used for deterministic resume tailoring and rendering.

Your task is NOT to rewrite the resume.
Your task is NOT to improve content.
Your task is ONLY to classify the existing template structure.

You will receive a parsed resume template with stable IDs assigned by the parser.

The parser has already identified:
- sections
- paragraphs
- roles (for experience-like sections, when detectable)
- raw heading text
- paragraph text

You must return JSON only.

GOAL

Produce a structured classification that maps the parsed template into canonical semantic section/block types and rewrite policies.

This classification will later be used to:
- preserve non-editable parts of the template
- rewrite only allowed parts
- map tailored LLM output back to the correct template sections/paragraphs deterministically

CORE PRINCIPLES

1. Preserve parser-assigned IDs exactly.
2. Do NOT invent or modify IDs.
3. Do NOT rewrite resume text.
4. Do NOT add validation commentary, explanations, or prose.
5. Output JSON only.
6. Prefer conservative classification when uncertain.
7. Do NOT mark sections as editable unless they are clearly intended for tailoring.

SECTION-LEVEL SEMANTIC TYPES

Allowed values for section.semantic_type:
- summary
- skills
- experience
- education
- projects
- additional
- other

SECTION-LEVEL REWRITE POLICIES

Allowed values for section.rewrite_policy:
- rewrite_body
- rewrite_bullets_only
- preserve

Interpretation:
- rewrite_body:
  body text may be replaced or rewritten later
- rewrite_bullets_only:
  only bullet/body content within roles may be rewritten later; headings/meta stay preserved
- preserve:
  preserve section as-is

BLOCK-LEVEL SEMANTIC TYPES

Allowed values for block.semantic_type:
- summary_paragraph
- skills_paragraph
- role_header
- role_meta
- bullet
- education_entry
- project_entry
- additional_item
- other_paragraph

BLOCK-LEVEL REWRITE POLICIES

Allowed values for block.rewrite_policy:
- rewrite_text
- preserve

CLASSIFICATION GUIDELINES

1. Summary-like sections
Examples:
- PROFILE
- SUMMARY
- PROFESSIONAL SUMMARY
- ABOUT
These usually become:
- section.semantic_type = summary
- section.rewrite_policy = rewrite_body

2. Skills-like sections
Examples:
- CORE COMPETENCIES
- TECHNICAL SKILLS
- SKILLS
These usually become:
- section.semantic_type = skills
- section.rewrite_policy = rewrite_body

3. Experience-like sections
Examples:
- EXPERIENCE
- PROFESSIONAL EXPERIENCE
- EMPLOYMENT
These usually become:
- section.semantic_type = experience
- section.rewrite_policy = rewrite_bullets_only
- preserve_heading = true
- preserve_body_structure = true

Within experience:
- role headers => preserve
- role meta/date/location => preserve
- bullets/body lines => rewrite_text

4. Education
Usually:
- section.semantic_type = education
- section.rewrite_policy = preserve

5. Projects
Usually:
- section.semantic_type = projects
- preserve unless there is a future business decision to rewrite them

6. Additional / miscellaneous
Examples:
- ADDITIONAL INFORMATION
- LANGUAGES
- WORK AUTHORIZATION
- CERTIFICATIONS
Usually:
- section.semantic_type = additional
- section.rewrite_policy = preserve

7. Unknown or non-standard sections
If unclear, classify as:
- section.semantic_type = other
- section.rewrite_policy = preserve

IMPORTANT PRESERVATION RULES

Default preserve behavior for:
- contact information
- education
- certifications
- languages
- work authorization
- miscellaneous non-standard sections unless clearly summary/skills

Default rewrite behavior for:
- summary section body
- skills section body
- experience bullets/body content only

DISPLAY TITLE

For each section, provide:
- raw_title = original heading text from template if present
- display_title = canonical human-readable title

Examples:
- raw_title: "PROFILE" -> display_title: "Professional Summary"
- raw_title: "CORE COMPETENCIES" -> display_title: "Technical Skills"
- raw_title: "PROFESSIONAL EXPERIENCE" -> display_title: "Experience"

If the raw title is already appropriate, display_title may match it semantically in normalized form.
