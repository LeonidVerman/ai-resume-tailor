CLASSIFY TEMPLATE RESUME — v6.3-role-normalization

GENERAL EXPERIENCE ROLE RULES

Every experience role MUST own nearby body paragraphs until the next role begins.

A role may contain:
- role_header
- role_meta
- role_achievement_bullet
- role_responsibility_bullet
- role_intro
- role_highlight
- role_project_label
- role_project_context
- role_key_technologies
- role_tech_stack
- role_tools
- role_nested_detail
- role_freeform_note

EMPTY ROLE RULES

Do NOT leave roles with empty body_blocks if nearby experience content exists.

If nearby paragraphs clearly belong to a role:
- attach them to that role
- classify them appropriately

ROLE SPLIT RULES

If a new role_header or role_meta appears after body content has started:
- close the current role immediately
- start a new role
- never keep role_header or role_meta inside body_blocks

HEADER / META CANONICALIZATION

A paragraph must belong to ONE semantic ownership category only.

If a paragraph behaves like role_header:
- store it only in header_blocks

If a paragraph behaves like role_meta:
- store it only in meta_blocks

Do NOT duplicate the same para_id into both header_blocks and meta_blocks unless absolutely unavoidable.

GENERIC COMPANY / LOCATION RULES

Company/location/date lines are metadata or contextual intro content.

They are NEVER:
- role_tools
- role_key_technologies
- role_tech_stack

Technical classifications must only be used for genuine technology/tool/stack content.

PRESERVE RULES

Preserve:
- technology stack sections
- key technologies sections
- tools sections
- project labels
- nested details
- highlights
- contextual project paragraphs

Rewrite from LLM:
- normal responsibility bullets
- normal achievement bullets

MULTI-ROLE CHAIN RULES

Long experience chains must split cleanly into separate roles.

If a paragraph indicates a new role boundary:
- terminate the previous role
- start a new role immediately

Do not absorb multiple companies/positions into one giant role.
