- CANDIDATE_PROFILE

GOAL

Produce a complete v2.1 TailoringPlan JSON that:
- Identifies real hiring themes
- Maps sufficient evidence per theme tier
- Avoids unsupported JD-only concepts
- Forces architectural reinterpretation where appropriate
- Passes strict schema validation and evidence saturation validation

------------------------------------------------------------
ABSOLUTE RULES
------------------------------------------------------------

1) Do NOT invent technologies, tools, vendors, protocols, metrics, titles, or scope.
2) All claims must be traceable to MASTER_RESUME or CANDIDATE_PROFILE.
3) Evidence quotes MUST be <= 25 words.
4) role_level must be exactly one of: junior, mid, senior, director.
5) Total bullets_to_reframe across resume MUST be >= 6.
6) If a JD concept is unsupported, translate it to a supported adjacent theme.

------------------------------------------------------------
STRICT JSON TYPE ENFORCEMENT
------------------------------------------------------------

The following fields MUST ALWAYS be arrays, even if they contain only one element:

- jd_top_themes
- evidence_map
- evidence_map[].evidence
- resume_strategy.experience
- role_repositioning_intent
- bullet_allocation_plan
- theme_priority.primary
- theme_priority.secondary
- theme_priority.supporting

You MUST NOT replace arrays with objects.

Incorrect:
"experience": { ... }

Correct:
"experience": [ { ... } ]

Incorrect:
"evidence_map": { ... }

Correct:
"evidence_map": [ { ... } ]

------------------------------------------------------------
STRICT SCHEMA REQUIREMENTS
------------------------------------------------------------

A) jd_top_themes MUST be an array of objects.
Each object MUST contain exactly:
- theme
- why_important
- keywords (array of strings)

Do NOT include priority inside jd_top_themes items.

B) evidence_map MUST be an array of objects.
Each evidence_map item MUST contain:
- theme
- evidence (array of evidence objects)
- gaps (array of strings)
- safe_translation (array of strings)

Each evidence object MUST contain exactly:
- source
- location
- quote
- allowed_claims (array)

Evidence MUST NOT be strings.

C) resume_strategy.experience MUST be an array of objects.

D) theme_priority MUST include:
- primary (array)
- secondary (array)
- supporting (array)

E) evidence_saturation_rules MUST include:
- primary_theme_min_evidence: 3
- secondary_theme_min_evidence: 2
- supporting_theme_min_evidence: 1

F) role_repositioning_intent MUST include entries for all high-priority roles.

G) bullet_allocation_plan MUST include entries for the top 2 roles.

------------------------------------------------------------
CONTENT REQUIREMENTS
------------------------------------------------------------

1) 5 to 7 jd_top_themes.
2) primary: 1 to 2 themes.
3) secondary: 2 to 3 themes.
4) supporting: remaining themes.
5) Every theme appears in exactly one tier.

   - primary >= 3 evidence items

Before assigning a theme to primary or secondary,
ensure evidence minimums can be met.
